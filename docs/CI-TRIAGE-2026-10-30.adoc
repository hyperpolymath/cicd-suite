== What to reuse; what not to swap in blindly

* Keep the suite's componentised audit, tool-absence exit-2 contract,
  negative controls, planted prover controls, caller SHA verification and
  transitive-lock guards. These address actual previously observed failures.
* Prefer repo-specific compiler/test/prover commands over filename existence
  checks. Governance, linting, security and functional correctness are
  complementary, not substitutes.
* The suite's manifest wrapper already supports distinct narrow DEED/K9
  exclusions. First fix validator subject selection or document classification;
  an estate-wide suffix exemption would hide real malformed manifests.
* `semantic-audit` and PRAT remain out of the enforcing workflow. Squabbler
  now exists but is not the imagined semantic audit command. Corrected the
  obsolete README assertion; no stub was promoted to assurance.
* The proposed fast secret-scan execution model must be implemented and
  measured upstream before switching consumers. No replacement was deployed.
