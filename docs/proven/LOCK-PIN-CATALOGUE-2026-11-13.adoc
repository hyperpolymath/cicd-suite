= Lock and pin checkers across the estate, 2026-11-13

This catalogue is the evidence base for the first proven slice. It was built
by reading file headers, messages and test names in four repositories:

* `metadatastician/standards` at `c58aa72` (S);
* this repository at `24b244a` (P);
* `hyperpolymath/gitbot-fleet` at `7fc2778` (G);
* `hyperpolymath/cicd-squabbler` at `09e6790` (Q).

No script was run. The reason codes are the ones in `ARCHITECTURE.adoc` in this
directory, and no checker uses them as identifiers. Mapping each checker to a
code was a judgement, and a row marked "unclear" was not resolved.

== The finding that shapes the slice

The same defect is decided by several implementations, and they disagree.

* *Lock sync: three copies.*
** S `scripts/check-lock-sync.sh` checks the exact set of `uses:`, including
   job-level calls. It requires `[]` for a workflow with no remote actions, and
   flags records that nothing uses.
** G `scripts/check-lock-sync.sh` reads step-level `uses:` only, and accepts a
   missing job-level ref.
** Q `scripts/check-lock-sync.sh` is an older copy of the same script.
+
gitbot-fleet's own audit (`audits/lock-closure-2026-10-31/REPORT.md`, item M9)
records the split: G's copy was green while five reusable callers ended with
zero jobs.

* *Self-SHA leaf: seven implementations with different exemptions.*
** S `scripts/check-lock-pin-contract.sh` exempts a caller-side record: one
   that carries a nested `uses:` list and is named by a job-level reusable
   caller (standards#1290).
** P `scripts/check-lock-pin-contract.sh` has no exemption and flags every
   40-hex `ref`. Verified by reading both scripts on 2026-11-13.
** Q `self_sha_lock_records` (`crates/squabble-core/src/rules.rs`) exempts a key
   only when a job-level caller names it. A nested `uses:` list is not an
   exemption.
** The other four are G `fix-lock-self-sha-refs.sh`, S `lock-selfcheck.sh`,
   G `audit-lock-closure.sh` and G's Rust `workflow-lock-audit`.
+
The proven model must decide this exemption once, from runner evidence. Every
copy then conforms to that decision.

* *Missing transitive edge: seven implementations.*
** S `check-lock-sync.sh` covers local composites.
** S `check-reusable-closure.sh` checks against a reviewed baseline.
** S `complete-job-refs.sh` and S `close-lock.sh` are writers.
** P `tests/lock-transitive-closure.sh` covers `$/` composites only.
** G `audit-lock-closure.sh` checks against receipts.
** G `audit-pinned-reusable-sources.sh` checks against git objects.
** G's Rust tool reports `MISSING-TRANSITIVE-RECORD`.

* *Illegal `$/` refs.* S and P apply different policies.

* *Stale ref.* The name means different things in different tools. G's Rust
  tool uses `STALE-WORKFLOW` for a lock entry whose workflow file is absent.

== Defects that no checker covers

* *OwnerIdDrift.* No checker compares `owner_id` with the live owner.
** S `check-lock-pin-contract.sh` and S `check-lock-sync.sh` only check that the
   field is present and is a positive integer.
** S `relock-standards-pin.sh` hard-codes `297579217` for the standards record
   instead of looking it up.
** Q SQ-LOCK-03 has a recipe but no detector.
* *Moved owner, at lock level.* Moves are detected and fixed only in workflow
  YAML (S applier, S `propagate-workflow-pins.sh`). Nothing checks that lock
  keys and `owner_id` follow a transfer. The consumer of G
  `scripts/lib/moved-repositories.tsv` is unclear.
* *Moved tag.* Nothing checks that a `ref:` tag still points at the pinned SHA.
  S `check-lock-pin-contract.sh` declares this out of scope. It was observed in
  G's audit, item M11 (`dtolnay/rust-toolchain@v1`, two commits), and in
  standards run 39286638218.
* *Blind empty entry.* It is covered only implicitly, by S `check-lock-sync.sh`
  "refs missing" and by G `audit-lock-closure.sh`. No check names it.
