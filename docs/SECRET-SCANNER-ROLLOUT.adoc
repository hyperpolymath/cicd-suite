= Bounded scanner implementation and staged rollout

== Current boundary

The suite now carries an implementation, not only a specification:

* `actions/secret-scan-check/{install,control,check,test}.sh`, composite action;
* `.github/workflows/secret-scanner-reusable.yml`;
* `templates/secret-scanner-caller.yml`;
* `.github/workflows/secret-scanner-self-test.yml` for real-binary controls.

No estate deployment or performance success is implied by file creation.
Full history is the default. PR-range mode requires an explicit opt-in;
non-PR runs always scan full history. Local tests use a stand-in only when
GITLEAKS_BIN is unset and explicitly announce that limitation. The same
fixtures must pass against the pinned real detector on GitHub runners.

The baseline is vendored from standards at
1725bebd3773ea25627479f813283abf1c497a85 with attribution. Its existing
exceptions are not newly validated by this import. Repo-local config remains
supported and must pass the synthetic detector controls. The original
specialised Rust/shell heuristic jobs are not included; do not retire them
on the strength of generic Gitleaks controls alone.

== Ordered rollout

. Publish the implementation on the fixed Arena branch; run real-detector CI.
. Add a SHA-pinned caller canary in cicd-suite while retaining the old scanner
  as a visibly separate legacy check. Do not have two workflows emit the same
  required context; the new caller must own `scan / gitleaks` unambiguously.
. Confirm caller resolution, actual startup, planted controls, tree/history
  scans, fork behaviour and current-head check context. Resolve any historical
  leaks, policy rejection or timeout rather than suppressing it.
. Compare old Rust/shell-specific detection with the new scanner. Preserve
  unique rules, test intentional suppressions, and obtain security-owner
  approval for any coverage changes.
. Propose consumer migration PRs in small batches, keeping each consumer's
  default branch, triggers, local exceptions, locks and supplementary checks.
  Use one reviewed full SHA and an owner/repo admission pattern only if policy
  evidence requires it. No organisation-wide policy weakening.
. Increase batch size only after real canaries pass. Report failures by
  repository/head/cause and stop the batch on a shared regression. Preserve
  old caller content/pins for rollback. Recheck required-context identity and
  missing-job runs separately from the visible check rollup.

== Assistance that may be needed

The integration cannot currently read Actions admission settings or some
classic-protection settings (403). An owner may need to inspect the precise
startup validation error and approve a minimal admission change. No token,
password or secret needs to be supplied in chat. Human approval is also
needed before retiring unique scanner coverage or accepting a new history
coverage boundary. Neither is solved by admin-merging.
