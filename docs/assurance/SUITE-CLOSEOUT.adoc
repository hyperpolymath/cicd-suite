== Scope and sequencing

The priority is cicd-suite itself. This thread owns the shared catalogue,
assurance evidence, runtime gates and their regression controls. Other repository
PRs are evidence sources and independently owned repairs, not a reason to ask
the owner to keep moving between threads. Broad deployment is deferred. A narrow
consumer canary is appropriate when needed to exercise shared machinery that
fixtures cannot prove. Full-history scanning remains the default.

No new clades are necessary to express the current 32 actions. Additional clades
may be proposed where useful; empty categories and invented capabilities are not
completion criteria. Observing a gap does not silently approve a new product.

== Suite lock-map finding — investigation, not a completed fix

At the inspected suite source:

* Four workflow keys exist in schema v0.0.2 actions.lock, for 14 workflow files.
  The ratio alone is not a defect: not every file is managed by the lock tool.
* The main-estate-audit workflow carries a managed header but has no lock-map key.
  The language self-test has a map key without that header. These are concrete
  consistency observations, not proof that every omitted workflow is broken.
* Checkout is represented under its tag key, while several workflows use the
  literal SHA. The existing representation guard accepts either valid form;
  that is not a complete workflow-to-lock coverage proof.
* The current transitive-closure test iterates workflows already in the map.
  It cannot, by that loop alone, detect an omitted workflow key.
* The estate audit invokes action sources at historical published `c519c452...`,
  not the current working action tree. Its green run is not blanket evidence
  for every action implementation currently being edited.

Required next disposition: inspect intended management scope and actual direct,
composite and reusable edges with a real YAML parser; distinguish intentional
unmanaged full-SHA references from missing managed coverage; design omitted-key
and dropped-edge mutants. Preserve provenance and runner semantics. Do not add
invented reusable lock entries, remove headers to bypass enforcement, or blindly
regenerate unrelated pins. This PR does not modify actions.lock or claim closure
repaired. The local sandbox lacks mikefarah yq, so yq-based inspection is not
reported as run.
