certificate. Tested bases: cicd-suite `20fb1b1`, proven-tests-and-benches

== CI defects and repairs

The shared gate previously omitted both tools' strict coverage flags. It now
requests `pons scan --fail-on-skips --fail-on warn` and
`panic-attack assail --fail-on-incomplete`, runs both, and has a configurable
1..3600 second deadline (default 180 seconds, five-second kill grace).
Incomplete coverage or process failure prevents passing. panic assail findings
are still report-only: this gate does not invent a severity policy for that CLI.

Proven Tests main run 41694405362 stopped at REUSE. Its installer also accepts
numeric versions from CI but upstream release tags require `v`; release-ref
normalisation, invalid-ref rejection and controls are added at the producer.
Panic's scheduled framework run 41390102464 demonstrates the same tag fault in
its older pinned installer; the caller now supplies the required prefix.

No checks, proof fixtures, required contexts or failing alerts are deleted to
obtain green. Hosted acceptance of the new changes remains separate from local
results. Existing zero-job governance/Hypatia/secret/mirror failures need their
own current-head receipts and migration fixes.

== Proof structure and outstanding work

* Pons: executable AST/CFG/dataflow and explicit protocol trace models. No
  general source-to-model soundness theorem, complete solver integration or
  proof of scanner correctness. Creusot lane presence is not such a proof.
* panic-attack: Idris models cover selected classification, comment-stripping
  and conditional attestation properties. Rust property tests are experiments;
  they do not prove all implementations refine those models. The three ignored
  baseline tests and GUI/Chapel paths remain outside these runs.
* Proven Tests: typed evidence and coverage derivation, tropical laws and test
  taxonomy. JSON conformance does not authenticate a theorem or execution.
  Live Idris2 0.7.0 results are now 41/41 framework, 56/56 type-safe and
  110/110 specification checks. Eight SafeOrdering law checks compiled and ran
  against proven at `53600326ca31f6f99767c5371cc77af2dade996c`. Four benchmark
  checksums and the regression gate passed. Local generated executable modes
  needed repair; hosted framework run 41815922308 subsequently passed.
  These are scoped laws and experiments, not an end-to-end implementation proof.
* Suite PR #74: experimental Idris verdict kernel is not merged. Review still
  flags acceptance of stale/unstarted advisory observations and PR-head receipt
  attribution. Address these before calling it a verified CI decision engine.
* Hypatia: the proof ledger distinguishes model proofs from Elixir refinement.
  Its neural coordinator is documented as five components; neural scores must
  never upgrade incomplete coverage or correlated heuristics to proof. Existing
  ingestion issue panic-attack#117 and Hypatia#984 are the appropriate routing
  points for provenance, execution truth and qualified learning.
* proven: its ledger explicitly records owed declarations and model/FFI gaps.
  Recheck actual owning modules before importing any safety claim.
* proven-servers: its ledger establishes no repository-wide build or protocol
  proof. Model/Idris → Zig → C ABI → language binding correspondence needs
  executable cross-boundary tests and separate refinement obligations.

paths with the suite's lock deonboarding procedure. All six reusable lanes
still startup-failed. Both repositories' own lock gates also rejected the
changed boundary. These experimental changes were reverted; neither lock
gate was weakened. Migration needs the consumer lock contract, callee lock
state and repository Actions admission policy to agree.

and counter controls reproduced 11 failures in the Python validator before
repair, with corresponding Rust changes. The 2,000-case seed-1371 shape
experiment returned 795 violations, 195 malformed outcomes and 1,010 accepted
mutations without unexpected exceptions. Optional-field mutations may remain
valid; these numbers are not a precision or recall measurement.

compiling a proof module does not validate arbitrary DISCHARGED prose markers
or establish foreign-implementation correspondence.
