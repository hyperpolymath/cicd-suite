= Badge Applicability and Metrics Evidence Repair
:toc:

== Scope and classification

`badges-check` and `metrics-check` remain *advisory*. Their zero exit status
does not certify accreditation, scanner execution, or proof correctness.
This change repairs what they report, without adding applicability overrides,
removing accreditation recommendations, or changing Actions policy.

The originating observation was
https://github.com/hyperpolymath/residual-evidence-types/actions/runs/41674254427/job/126050482689[estate audit run 41674254427].
Its old aggregate workflow called composites at
`0da816c05ae7486671d863e07935f93981c0c2d5`. A generic `src/` directory caused
two incorrect Idris warnings in an Agda repository. The metrics step emitted
three integer-comparison errors and then reported `Status: PROVEN`, even
though it ran no prover. Missing scanner logs were reported as zero errors.

== Changed observations

Badge applicability now requires an existing, Git-tracked `.idr`, `.lidr`, or
`.ipkg` file. Nested paths and filenames containing whitespace are supported.
An untracked file, deleted tracked file, or generic source directory does not
establish Idris applicability. Failed source discovery is explicitly
unassessed. Existing GLAMA, Greenweb, OpenSSF, License, and applicable
Idris/RSR recommendations remain; the action does not verify their standing.
Missing or unreadable README files leave badge presence unassessed. The
presence checks distinguish a successful grep non-match from a read/tool
failure, including the Idris-specific recommendations.

Metrics now count lines containing the literal uppercase marker `ERROR` only
when the named log is readable. A zero count is a text observation, not a
scanner result. Missing or unreadable logs are unassessed. No source keyword
search can promote the proof status to a verdict. Compiler/prover receipts
remain necessary evidence for proof claims.

== Local controls

link:../../actions/badges-check/test.sh[Badge controls] and
link:../../actions/metrics-check/test.sh[metrics controls] execute the action
scripts under GitHub's composite Bash options:

[source,bash]
----
bash --noprofile --norc -e -o pipefail
----

The badge controls cover Agda-only sources, tracked and untracked Idris,
packages without a source directory, deleted sources, literate Idris, missing
or non-file README, discovery failure, and unchanged accreditation advice.
A deterministic grep failure leaves all six applicable badge checks
unassessed; this does not rely on file permissions that root can bypass. A
syntax-valid mutant restoring the original `src/` shortcut must produce the
specific false Idris warnings, or the control suite fails.

The metrics controls cover absent logs, non-file paths, counting-tool failure,
zero and nonzero counts, line-count semantics, and source keywords that must
never become proof evidence. These tests validate reporting behavior; they
do not execute Pons, Panic Attack, or a prover.

== Publication boundary

The aggregate workflow pins composite implementations separately from its
own workflow revision. A source fix must be followed by an update to those
literal composite SHAs; `tests/lock-transitive-closure.sh` checks that each
referenced composite matches the published source. Consumers must then pin
the resulting reviewed main revision and validate their own caller and lock
requirements. A consumer pin change alone cannot select an unpublished
working-tree repair.
