== cicd-suite

Composite GitHub Actions for estate-wide CI/CD auditing. They are run by
the reusable workflow `+.github/workflows/main-estate-audit.yml+`. Each
repository *calls* that workflow from a ten-line caller; it does not copy
it (see _Consuming it_).

The audit reports five component checks, one check run each:

[cols="1,3",options="header"]
|===
|Check |Gates
|`governance` |required-files · spdx-license · affirmation · referencing
|`hygiene` |code-hygiene · formatting · linguist · secrets · vaulted-tokens
|`manifests` |manifest · recipes-set
|`languages` |idris2-abi · zig-unified-api-adapter · proof-runner · boj-cartridge
|`advisory` |the nine advisory gates below; this check cannot fail, by design
|===

Within a component every gate runs even after an earlier gate fails, so one
push reports every failing gate. Before this change one job ran all 26 in
sequence, and the first failure hid the rest behind "estate-audit: failing
after 8s".

=== Status

Published 2026-08-07. Defects (1)–(3) are *fixed and verified against two
live estate repositories*; (4) is partly fixed; (5) is closed by removing
the stubs from the workflow; (6) is open.

Before wiring this into a repository, read _Known defects_ and _Consuming
it_.

=== What actually enforces

Of 26 actions, *15 can fail a build and 11 cannot* — and the 11 are not
one kind of thing. Conflating them was the original error.

[width="100%",cols="34%,33%,33%",options="header",]
|===
|Class |Actions |Meaning
|*Enforcing* (15) |affirmation · boj-cartridge · code-hygiene ·
*formatting* · idris2-abi · linguist · manifest · proof-runner ·
*recipes-set* · referencing · required-files · secrets · spdx-license ·
vaulted-tokens · zig-unified-api-adapter |Can fail. A green tick means something.

|*Advisory* (9) |badges · contractile-validation · custom-tools · gitsea
· hosting · metrics · tests-benches · trust-humans · www-compliance |Do
real work, warn on genuinely soft findings. Failing the estate over a
missing Keybase link would be worse than not checking.

|*Unimplemented* (2) |prat · semantic-audit |Stubs. Not referenced by the
audit workflow. See (5).
|===

`+formatting+` and `+recipes-set+` moved out of the toothless column;
the remaining advisory nine are advisory _by design_, which is
defensible — provided nobody reads their green tick as a guarantee.
Renaming them `+*-advisory+` would settle that permanently.

Verify at any time:

[source,sh]
----
for a in actions/*/; do
  grep -q 'exit 1' "$a/action.yml" && echo "ENFORCE $(basename $a)" || echo "advise  $(basename $a)"
done
----

A gate that cannot fail is worse than no gate, because it is credited as
assurance. The advisory 13 should either grow teeth or be renamed so
nobody reads their green tick as a guarantee.

=== Known defects

*1. FIXED — `+code-hygiene-check+` scanned for the word, not the
marker.* It ran one case-insensitive, unanchored `+git grep+` over the
whole tree, so "`admit`" matched "`admitted`", "`sorry`" matched
ordinary English, any document _discussing_ a marker failed, and
`+believe_me+` failed repos whose sanctioned axioms are their declared
trusted base. Measured *112* matching files in one repo and *313* in
another. Now two scans with different semantics — debt markers
case-sensitive and whole-word in source only; circumventions in proof
languages only, with comments filtered. Repos may exempt paths via
`+.cicd-hygiene-allow+`. Result: *112 → 2* and *313 → 3*, all true
positives.

*2. FIXED — `+required-files-check+` manufactured filler.* Presence-only
checking meant the cheapest way to pass was template boilerplate, and
that is exactly what happened in the estate. It now checks presence,
then format, then substance: documents need real content and no
placeholders, `+ARCHITECTURE+` must name a directory that actually
exists, and `+MAINTAINERS+` must mention the repository owner — which
catches a template shipping its author’s handle. `+CODEOWNERS+` is
judged on whether it assigns an owner, not on length.

*3. FIXED — the suite contradicted itself.* `+required-files-check+`
hard-failed a repo for lacking `+GOVERNANCE.md+` while
`+formatting-check+` warned that same file should be `+.adoc+`.
Required-files now accepts every policy-legal form, and formatting-check
owns the preference. Verified: a repo passes both gates with `+.adoc+`
(silently) or with `+.md+` (with a nudge).

*4. PARTLY FIXED — the toothless column is down from 13 to 11, and now
triaged.* `+recipes-set+` was a stub that printed "`Checking Justfile
syntax…`" with the command commented out and then declared success; it
now parse-checks Justfiles and Makefiles and fails on a file that does
not parse. `+formatting+` gained teeth in (3). The nine remaining
advisories are advisory by design and defensible; the honest fix for
them is a rename to `+*-advisory+`, not teeth.

*5. CLOSED — two actions are unimplemented stubs, and the workflow no
longer runs them.*

* `+semantic-audit+` is pure `+echo+` with "`Placeholder for actual
invocation`"; its real body is `+cicd-squabbler audit --semantic+`, and
*`+cicd-squabbler+` does not exist yet*. It cannot be implemented, only
parked.
* `+prat+` claims to validate "`PRAT testing`", but *PRAT is defined
nowhere in the estate* — a search of every repository turns up only
further copies of the workflow that calls it. Its current check passes
any repository that has a `+tests/+` directory _or_ contains the letters
"`prat`" anywhere. It cannot be honestly implemented until somebody says
what PRAT is.

A stub that prints success cannot be credited as assurance, so neither
step is in `+main-estate-audit.yml+` any more. The two directories stay
under `+actions/+` for now, for two reasons. Repositories still running a
pre-caller copy of the workflow reference them by path. And
`+tests/lock-transitive-closure.sh+` requires that the SHA the workflow
pins serves the whole `+actions/+` tree at HEAD. Move them to `+draft/+`
once the estate runs the caller (see _Consuming it_).

*6. OPEN — six actions use bare `+git grep+`* with no path restriction
(`+idris2-abi+`, `+metrics+`, `+secrets+`, `+spdx-license+`,
`+vaulted-tokens+`, `+zig-unified-api-adapter+`) and may inherit a milder form of
defect (1).

=== Blast radius

An earlier `+rollout_estate.sh+` copied the whole workflow into *199
repositories*. Each copy froze at whatever cicd-suite commit its
`+actions.lock+` held. That is why a gate fixed here kept failing
downstream. The composite-shell fix to required-files (#32, 2026-09-22)
had still not reached hyperpolymath/marches on 2026-10-14, because its
lock held `+5a10b72+`, the commit before it. The caller replaces those
copies.

The workflow now has `+permissions: contents: read+` and pins
`+actions/checkout+` and every gate by full SHA.

=== Consuming it

A repository calls the audit; it does not copy it. Three pieces:

. `+templates/estate-audit-caller.yml+` becomes
`+.github/workflows/main-estate-audit.yml+`, with `+__CICD_SUITE_SHA__+`
replaced by a full cicd-suite commit SHA:
+
[source,yaml]
----
jobs:
  estate:
    uses: hyperpolymath/cicd-suite/.github/workflows/main-estate-audit.yml@<40-hex sha> # cicd-suite main
----
+
Pin a full SHA, never `+@main+` or a tag: the account enforces
`+sha_pinning_required+`, and `+@main+` would silently change the gate in
every consuming repository at once.
. The caller must be *de-onboarded* from the repository's
`+actions.lock+`. Onboarded, a cross-repository reusable-workflow call
startup-fails with zero jobs. `+scripts/deonboard-estate-audit.sh <repo>+`
removes the entry and prunes the dependencies only it reached. It needs
mikefarah `+yq+` v4, and it is idempotent.
. `+templates/track-estate-audit.yml+` becomes
`+.github/workflows/track-estate-audit.yml+`. Weekly, it opens a PR that
moves the pin to cicd-suite HEAD; that PR's own audit run is the check.
It needs an `+AUTOMATION_TOKEN+` secret (a fine-grained token on that
repository with Contents, Pull requests and Workflows set to read/write),
because `+GITHUB_TOKEN+` may not write under `+.github/workflows/+`.

`+rollout_estate.sh+` does all three for every local estate clone. It
writes files and does not commit them.
